# Finsight release

The release branch is `finsight-release` in `aonethika/fintrckr`. It is a clean monorepo containing `frontend/` and `backend/`, with no local databases, private environment files, receipts, screenshots or dependency directories. Existing `main` and `master` branches are not rewritten. The requested deployment replaces the existing Fintrckr Netlify site and Render backend using this release branch.

## Render

Update the existing `fintrckr` Render service to the `finsight-release` branch and clear its old root-directory override. Use the build/start/health settings in `render.yaml`. It builds the Vite UI and serves it alongside the API, so the API URL can also serve the app directly. Node is pinned in `.node-version`. No paid resources are required by this configuration.

For the existing `fintrckr.netlify.app` site, select this branch and use the root `netlify.toml`: base `frontend`, command `npm run build`, publish `dist`. The build sets `VITE_API_URL=https://fintrckr.onrender.com/api`. Preserve the existing Netlify site identity and URL. The Render service sets `FRONTEND_URL=https://fintrckr.netlify.app` for cross-origin API access.

Required private settings:

- `MONGO_URI`: a reachable MongoDB Atlas or other production MongoDB replica-set URI. The current local URI cannot be used on Render. Give Render's service access to this database using your database provider's network controls.
- `JWT_SECRET`: generated by Render. Keep it stable across deploys to preserve sessions.
- `FINSIGHT_AI_API_KEY`: the original AI provider key, or another compatible provider's key. Set `FINSIGHT_AI_BASE_URL` and `FINSIGHT_AI_MODEL` to match it. The original provider account currently has insufficient credits.

The source contains no live credentials. Set the private values in Render's environment settings, not in Git or chat. For a different frontend host, update `FRONTEND_URL` on the API and `VITE_API_URL` during the frontend build. Render supplies its public URL for same-origin requests to the combined service.

Receipts uploaded through the combined workspace are stored as image data on their MongoDB transaction (maximum 2 MB per image), so no paid filesystem disk is required. Historical disk-based receipts and local records are not migrated automatically. No local test accounts are published to a separate production database.

Check `/api/health` for a `200` response and open `/login` after deployment. Create an account and verify saving and reloading a transaction before sharing the app. AI provider errors are shown explicitly and do not alter financial records.

Render's free service can sleep when idle. See [free-service limits](https://render.com/docs/free) and the [Blueprint reference](https://render.com/docs/blueprint-spec).

## Local verification

```powershell
cd frontend
npm ci
npm run build
npx eslint src/finsight src/main.jsx
cd ../backend
npm ci
npm test
```

`backend/tests/production.test.js` exercises the production app's static SPA routing, API 404s, CORS and safe error responses. Backend integration tests use isolated temporary databases, not the application database.
